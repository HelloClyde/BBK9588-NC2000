# BBK 9588 移植

这是 NC2000/NC2600 模拟器的 BBK 9588 实验移植。它使用
`bbk9588-bda-sdk` 的原生 BDA ABI、240×320 RGB565 framebuffer、触摸与物理按键、
22050 Hz 单声道 PCM，以及固件文件选择器。SDL、桌面线程和 C++ 标准库不进入目标程序。

## 构建

需要 PowerShell、Python 3 和 Git。首次构建会下载并校验 SDK 指定的 MIPS 交叉工具链：

```powershell
git submodule update --init sdk
.\tools\build_bbk9588.ps1
```

产物位于 `build\nc2000_bbk9588\NC2000.bda`。构建脚本也会保留 ELF、map 和 objdump
结果，并在打包时调用 SDK 校验器检查 BDA header、入口、图标区和 checksum。

需要单独检查 9588 PCM 输出时，可构建带一次性 1 秒测试音的诊断版本：

```powershell
.\tools\build_bbk9588.ps1 -DspSelfTest
```

正式发布时不要带 `-DspSelfTest`；普通构建不会生成测试音。

## ROM 文件

本项目不附带任何 ROM、NAND、NOR 或词典数据。固件来源、机型格式与免责声明请查看
[原 NC2000 Releases](https://github.com/wangyu-/NC2000/releases) 和
[原 NC2000 Wiki 的机型/内核说明](https://github.com/wangyu-/NC2000/wiki/%E5%88%87%E6%8D%A2%E4%B8%8D%E5%90%8C%E6%9C%BA%E5%9E%8B%E5%92%8C%E5%86%85%E6%A0%B8)。
请只使用你有权使用的真机 dump。

优先把同一套 dump 放到 9588 的 `B:\NC2000\`，三个文件必须
使用相同的基本文件名：

```text
B:\NC2000\35.nand    至少 34,603,008 byte（65,536 × 528）
B:\NC2000\35.nand0   启动区 dump，通常不超过 33,792 byte（64 × 528）
B:\NC2000\35.nor     524,288 byte
```

BDA 会按 `B:\NC2000\35.*`、`A:\NC2000\35.*` 的顺序检查完整的三文件套装。B 盘没有
时自动回退到 A 盘；两处都无效时，从 `A:\NC2000\` 打开 `.nand` 文件选择器。其余两个
文件会按基本文件名自动匹配。当前前端固定使用 NC2000 模式；NC2600 固件仍通过其 NAND
magic 识别。NC1020、NC3000 和 PC1000 尚未接入这个前端。

如使用 SDK 附带的独立测试 NAND，可在模拟器停止后把 ROM 副本装进去（不会改动源文件）：

```powershell
$EmulatorRoot = "C:\path\to\bbk9588-emulator"
$RomDir = "C:\path\to\your-rom-dumps"

& "$EmulatorRoot\python\python.exe" `
  .\tools\install_nc2000_roms_to_emulator.py `
  --emulator-root $EmulatorRoot `
  --nand "$EmulatorRoot\runtime\bda_test\bbk9588_nand.bin" `
  --rom-dir $RomDir --base-name 35
```

NAND 主体按 528-byte 页从文件按需读取，不会把 32 MiB dump 整体装进内存。已修改的
NAND 页会写回原 `.nand`，`.nand0` 和 `.nor` 在正常退出时保存。测试新 dump 前请先备份。

## 操作

- 屏幕上半部按 1× 显示原生 160×80 LCD，并在 240×120 区域内居中；下半部是完整触摸键盘。
- LCD 右侧空白区右上角的 `X` 使用系统确认框询问；选择“是”后保存并退出，选择“否”返回模拟器。
- 方向键和确认键映射到文曲星的方向键与输入键。
- 短按退出键映射为文曲星 `ESC`；按住约 0.8 秒正常保存并退出 BDA。
- `SAY` 放在第三排最右侧，便于直接测试发音；`PUP` 移到原 `SAY` 位置。
- 蜂鸣器和 SPDS104A DSP 语音混合后通过 22050 Hz PCM 输出。DSP 的 8000 Hz
  CELP/PCM 数据使用定点线性插值重采样，并保留原模拟器的 5000-sample busy 阈值。

## 性能

- 发布构建默认使用 `-O2`、LTO 和 section GC。
- 65C02 在 9588 上使用运行时 MIPS32 代码块 JIT；连续基本块最多合并 8 条指令，
  单指令块直接缓存对应的原生处理函数，非法指令和周期预算不足时回退到解释路径。
- JIT 对代码映射和自修改代码做校验。缓存键同时包含 16 位 PC 和实际 ROM/RAM bank
  映射，使用四路哈希避免同一地址在不同 bank 之间互相覆盖。写入失效粒度为 256 byte。
- 生成代码使用 2 MiB 缓存，并在执行前同步 9588 的数据缓存和指令缓存。缓存最多整体
  回收一次；再次写满后安全退化为缓存单指令原生处理器，避免字典 bank 扫描触发持续
  重编译、长时间不返回主循环和系统看门狗复位。
- LCD 只在 160×80 源缓冲变化时重绘、提交 framebuffer；软键盘只在按键高亮变化时重绘。
- DSP 解码后的 160/240-sample 帧会整块入队。字典 SAY 使用的 WORD 模式先收集体积很小的
  CELP 压缩帧，收到音节结束后按 100 Hz DSP 时钟每次只解一帧，避免整个单词在起音时同步解码卡住音频送数。
  首批语音会先缓冲 640 个 8 kHz sample（约 80 ms）再开始播放，以换取起音阶段的连续性。
  8 kHz 到 22.05 kHz 重采样和蜂鸣器时钟使用定点累加，避免每个音频采样的 64 位软件除法。
- 6502 执行批次为 2048 cycle，在降低外围调度开销的同时，仍保留约 0.4 ms 的
  中断/DSP 服务粒度。画面检查上限为 20 Hz，输入与 6502 执行不受该帧率限制。

## 真机诊断日志

BDA 启动后会把诊断信息追加到 `A:\NC2000\NC2000.LOG`；目录不可用时回退到
`A:\NC2000.LOG`。单个日志达到 512 KiB 后依次使用 `NC2001.LOG`、`NC2002.LOG`，
不会在下一次启动时覆盖刚发生死机的记录。

日志覆盖 ROM 路径、NOR/NAND 加载阶段、每 5 秒一次的 CPU 寄存器/内存映射/JIT
心跳、系统退出确认框、NAND/NOR 保存、音频和窗口关闭阶段，以及 assert/abort。新版
`JITLOG2` 的 `jit` 还记录哈希槽替换数和代码缓存写满后的安全退化块数。
字段顺序为 `compiled/calls/interpreter-fallback/cache-resets/max-block/replacements/cache-fallback`。
每行都使用真机已经验证过的 `open append -> write -> close` 方式立即落盘；死机重启后，
查看最后一行即可判断停在哪个阶段。日志是低频诊断写入，不会记录每条 65C02 指令或
每个按键。SAY 发音和音频队列排空期间会延后心跳落盘，避免闪存写入卡住语音关键路径；
下一条心跳的 `dsp` 末尾数值为当时未播放的 DSP sample 数。

## 当前限制

- 即时存档、桌面命令行、红外/串口主机桥接、快进界面和 LCD 残影滤镜没有接入。
- DSP 解码源码取自 `wangyu-/wqxdsp` 固定版本；9588 适配来源与改动见
  `dsp/UPSTREAM.md`。
- 已通过交叉编译、BDA 静态校验、9588 QEMU 启动和 35 ROM 实际单词发音测试。
  真机音量、持续发音、NAND 写回和整体性能仍建议使用合法 dump 复测。
